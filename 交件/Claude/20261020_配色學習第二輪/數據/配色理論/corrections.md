# theory 串修正紀錄（10-19）

依據獨立查核 `verify/verdict.json`。每一項都自己重算或重讀原文後才改。判 confirmed 的 claims 沒動（C16 只改公式名稱）。

## 1. C11 和田三造的隨機比較

- 原本：明度差、色相差、同色調「都沒有差別」（p 0.13–1.0）；筆記寫「這幾條教科書規則都解釋不了和田怎麼配」。
- 改成：明度差、色相差 ≥150°、同色調沒有測到差別（p 0.17–1.0）。色相差 <30° 是 11.7% 對 17.7%，p 約 0.09，在邊界。和田的同色相配對比較少，方向跟刻意拉開色相一致，但不顯著。只有 123 組，檢定力有限，不能說「沒有差別」。
- 依據：`wada.py` 改成每次重新抽 123 對，種子 11、2027 各跑 2 萬次，p 是 0.092、0.089。原本先抽一個固定的 2 萬對池再重抽，那個池的同色相比例剛好偏低（17.2%），p 才變成 0.128。查核用自己的程式算出 0.094–0.096，跟我的結果差在抽樣誤差內。標準誤 0.036（111 組兩色都有彩度），差 6 個百分點只約 1.7 個標準誤。
- 檔案：`wada_stats.json`（新鍵 `test_vs_weighted_random_fresh_123x20000x2seeds`、`power_note`）、`fig_wada.png`、筆記。

## 2. C13 Matsuda 模板

- 原本：隨機兩個色相放得進 T 型 99.8%。PUB #0172BB 只放得進 T、X。
- 改成：放得進 T 型 100%，X 型也是 100%。T 型是 180° 的半圈，任兩個色相一定放得進。PUB 放得進 V、L、mirror_L、T、Y、X。19 家有 18 家放得進至少一種，這點不變。
- 依據：原本旋轉只試 0.5° 一步，色相差接近 180° 的情形會漏掉。現在改成精確判定，只試「某個色相剛好落在扇形邊上」的角度。`hsv_h` 原本寫 `r/255 if r>1`，但 `ct.rgb` 回傳 0–255 的整數，所以 PUB 的 R=1 被當成了滿值。改成一律除以 255。重跑後只有 PUB 那一列變了，跟查核的 `v_matsuda.json` 逐列相同。
- 檔案：`matsuda_templates.py`、`matsuda_templates.json`、筆記。

## 3. C15 Goethe 權重與 Munsell

- 原本：「Munsell 最鮮色票」明度：紫 .3、綠 .5。重算面積比是 1:3.0、1:1.75、1:1.0，「跟 Goethe 很接近」。
- 改成：`real.py` 是 1943 年 renotation 資料裡落在 MacAdam 極限內的理論點，不是實體色票。紫的最高彩度 32 在明度 3 和 4 並列，綠的 28 在明度 5 和 6 並列，兩種取法都列出來：
  - 黃:紫 是 1:3.0 或 1:2.25。
  - 橘:藍 是 1:1.75。
  - 紅:綠 是 1:1.0 或 1:0.83。
  - 接不接近 Goethe，要看怎麼取。
- 依據：用 `load('real')` 自己列出各色相的最高彩度點。`real.py` 檔頭寫明 within MacAdam limits。
- 跟查核不同的一點：查核寫紅:綠 1:1.2，這是把方向寫反了。綠比紅亮，所以綠的面積較小：紅:綠 = 1:0.83，等於紅的面積是綠的 1.2 倍。
- 檔案：`area_balance.py`、`area_balance.json`、筆記。

## 4. C17 NCS 的冷暖兩端

- 原本：「最暖是橘、最冷是藍綠」，寫得像定論。筆記也寫「冷暖也有了明確的兩端」。
- 改成：這是 Briggs 的推測。他的推法是：多數分類把黃、紅算暖，藍、綠算冷，所以最暖「可能」是橘、最冷「可能」是藍綠。這不是 NCS 的規定。工程黃、深青的冷暖位置也改成「若照 Briggs 的推測」。
- 依據：重讀 `ch07-hue.md` 963 行，原文是 "one could suggest"。
- 檔案：筆記 NCS 段（含原 132 行）。

## 5. C24 各色相最鮮點的明度

- 原本：「黃綠色相（105–120°）最鮮點在 0.94」。
- 改成：最鮮點最亮的是 OKLCH 110° 附近，也就是 sRGB 純黃 #FFFF00（109.8°），明度 0.968。105° 和 120° 約 0.94。OKLCH 110° 是純黃，不是黃綠。工程黃那個色相的最鮮點約 0.786。
- 依據：原本每 15° 才取一點。這次沿 sRGB 立方體邊細取樣（六條邊各 20001 點），再內插到每 1°。最鮮點一定落在這幾條邊上。原有欄位重跑後數字不變。
- 檔案：`hue_contrast_map.py`、`hue_contrast_map.json`（新鍵 `cusp_fine`）、筆記。

## 6. 摘要與筆記的用詞

- 亮度比範圍：
  - 原本：2.87 到 7.33。
  - 改成：1.56（中灰）到 7.33（黑）。
  - 依據：C8 自己的數字，查核也確認過。
- Itten 七種對比：
  - 原本：七種都在同業找得到實例。
  - 改成：只有五種（色相、明暗、冷暖、補色、彩度）在單一 logo 裡有實例。面積對比沒有資料。同時對比是三家顏色拼成的示意。另一個彩度對比例子（Uisce Éireann 對 KAISER）是跨公司拼的。
  - 依據：`itten_examples.json`，以及原圖自己的標注。
- 深青底和靛藍底：
  - 原本：在模型裡幾乎一樣，差別只在色相誘導方向。
  - 改成：模型明度 J 只差 0.3（59.0 對 58.7），但兩個底並不一樣：亮度比 3.87 對 3.66，ΔE2000 52.7 對 56.2。CIECAM02 不算色相誘導。所謂誘導方向，只是把底色色相加 180° 推出來的。
  - 依據：用 colourtool 重算亮度比和 ΔE。
- 平衡面積公式：
  - 原本：兩條公式相差 2.5 倍，其中一條叫「Goethe 式」。
  - 改成：深青相差 2.5 倍，靛藍 1.7 倍，Kier 1.9 倍，SUEZ 1.3 倍。這條公式其實是面積與 CIELAB L* 成反比，所以改名「L* 倒數式」，它不是 Goethe 的權重表。C16 只改了這個名稱，數字沒變。
  - 依據：`area_balance.json` 新增欄位 `share_ratio_inverseL_over_VC`。
