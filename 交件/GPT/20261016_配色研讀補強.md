## 讓往後的比較更有依據

1. **先固定內容。** 對應樣本使用相同「崧淳」、公司全名與兩項工務，維持字體、字重、尺寸、留白和色塊位置；先改一個色彩變項。名稱先行是既有版面選擇，並非任何色票或 Logo 的採用。
2. **輸出前看有沒有變色。** Color.js 的轉換不自動等同座標已進入 sRGB；字串顯示可能已映射。Culori 的 `formatHex` 會截斷超界 RGB 並省略 alpha；能輸出 HEX 不代表原值合格。記錄來源版本、目標空間、方法、參數與前後數值。兩工具本次只研讀，未安裝或重跑。
3. **逐用途判斷。** 名稱、服務小字、表格底、線條、CCTV 註記各自檢查。單一色對合格，不推定整份文件、其他版本或其他透明度都合格。技術影像上的工項數據仍須來自真實資料，示意內容不得充作成果證據。
4. **將實材另行確認。** 待供應商、設備、紙材、膜材與表面處理確定後再打樣；記錄光線和觀看角度。現在不填通用 CMYK、油漆、車貼或反光規格。實材階段是後續方法，這次尚未進行。

Color.js 文件前後對色差方法的敘述有差異，Culori 也明言其映射與所引 CSS 方法略不同；W3C 2026-10-09 的 CSS Color 4 草案允許三種映射實作。因此後續數值工作必須固定方法與版本，不能宣稱所有瀏覽器／工具一定輸出同一數值。
