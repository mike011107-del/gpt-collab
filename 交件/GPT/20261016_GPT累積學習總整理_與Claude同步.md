## 二、從原作學到的配置方法

PR #9 記錄六位原作者：Brightwater／Glidden、Rucad／Ney Barão、Adiss／Hye Studio、Neara／Mubien、Kreo／Joynal Abedin、BAAS／Studio Krista。來源工作階段看過前四案的選定原作圖區及 Kreo 的 Pinterest 拼圖；Kreo 原頁需人機驗證，BAAS 未目視。PR #15 再補 KMK／Yury Akulin 的貨櫃與名片選定圖區。這些目視不是本次雲端重新看圖，也不是完整手冊逐頁閱讀。

可接續的取法：

1. 先分配色彩角色：公司辨識、正文閱讀、分區、資料意義各負責什麼，再比較面積。不能以固定三等份色票或一個面積比例套所有應用。
2. 白底和留白應讓真實內容清楚。清淤資料、CCTV 影像與註記需要自己的位置；灰色橢圓、假技術線、假編號、概念拆字或假印章不能充當工程實績，也沒有因案例好看就必須加入。
3. 名稱、公司全名、兩項服務建立可重複的關係；兩服務同等清楚。一致性來自固定結構，不能只重複同一 HEX 或替兩項服務各造一套符號。
4. 拉丁字體、切角字標、反白小字都要回到繁體中文筆畫與實際尺寸。Montserrat 或原案字型只屬原案，不構成「崧淳」選字或最佳字距的證據。
5. 示意圖能比較配置，不能證明商業採用、客戶信任、刺繡、印刷或其他實物效果。取法仍是本案推論。

## 五、色域、輸出與媒材

PR #15 對 Color.js、Culori、CSS Color 4 的研讀形成四步：**轉換座標 → 檢查色域 → 選定映射 → 格式輸出**。步驟不能互相代替。記工具版本、目標空間、映射方法／參數、前後座標、輸出與 alpha；有透明度先按實際背景合成，再檢查對比。

`toGamut` 可能改動物件；Culori `formatHex` 會裁切 RGB 超界並省略 alpha。能輸出 HEX 不表示原色在域內。Color.js 不同文件、Culori 與 CSS 草案的映射說明有差異，需固定版本和演算法；ΔE_OK 與 ΔE2000 不混成同一尺度。本次沒有安裝或執行這兩個套件，Claude 也只陳述自己重跑了其自寫映射程式。

ICC 描述檔、Adobe 指定條件軟打樣、Fogra 的紙色／增白劑／光澤各處理不同問題。文件可學，不證明目前設備已校準。HEX 不能普遍換一組 CMYK 或專色即稱一致；日後若進紙張製作，要指定輸出條件與樣張。這是方法界線，本輪不新增車身實材待辦。

## 七、AutoIP 的兩條學習記錄要分開

**GPT #25：** 已交 API 範例和本機模擬測試。學到的流程是取得規格、multipart prompt建立任務、用task_uuid輪詢、完成後下載；逾時續接UUID，不盲目重送建立任務的POST。規格取得失敗即停止、不跟隨重新導向、不覆寫既有檔，測試檢查金鑰遮蔽和不完整下載清理。原交件記10項模擬測試通過，本次同步未重跑。帶驗證的即時規格請求遭代理403，所以**沒有證實GPT已連上即時API、金鑰有效或實際生成成功**。官方套件兩份檔來自同一來源，模擬回應也有依賴，不能累計為多份獨立服務實測。

**Claude #24／#26：** 已交縮圖、程式、生成紀錄，陳述先生成空白場景、程式按指定色號貼色並保留光影，再以圖生圖修飾；提示色號本身不能保證生成色準。這是值得接續核實的方法，但我方本次只回讀說明，未重跑API、重取樣色差或獨立目視其圖。原始大圖未共用。

Claude 所報 ΔE_OK 0.06–0.20及修飾後≤0.004只對其記錄的取樣與場景成立；不能概括每個表面、陰影、輸出和後續生成都精準，更不能以單一小色差斷言所有人肉眼看不出。合成場景不證明真實業務成果；真實技術影像和公司資料仍須另有來源。舊API說明中的工程車prompt只是一段呼叫示例，本輪不再用它擴張車身工作。
