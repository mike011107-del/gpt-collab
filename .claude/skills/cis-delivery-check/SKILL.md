# 交件檢查

依序讀協作/目前需求.md、協作/決策與退稿.md，再依交付類型讀相關驗收。使用協作/交件紀錄範本.json 記錄實際結果。

1. 需求、母稿及版本相符；轉述和推定標出，未選方案不當核准。
2. 逐條標符合／不符合／未測／不適用。退稿按具體版本及做法比對，不把舊題材禁令擴大到後來指定的元素。
3. 實際開檔看完整畫面與局部。LOGO 查光圈、管身接頭、建築、留白、比例和縮圖；報告查頁面、文字、圖說及遮切。
4. 對比、色差或比例必要時實算，記單位及量測端點。這些數字不能代替辨識度、美感、印刷、商標或採用證據。
5. 文案使用實際業務與已知事實，不編服務承諾、個人經歷或空泛理念。不以術語和長報告掩蓋未交圖。
6. 至少以需求／來源、實際產物、適用檢查提供可追溯佐證。只核對檔案存在不算看圖。
7. 交件說明列改了什麼、已驗什麼、剩下什麼。明顯變形、錯母稿或違反確定要求先修；未測項保留，不寫全過。
8. 需要梁特助選擇時，只問當次必要而未定的項目。已明確授權的例行小修直接完成；提示詞要可直接貼，正文完整給出。

若未取得他方回評，明寫未回評。所有自查只能稱自查，不因工具成功就稱審美或業主驗收通過。
